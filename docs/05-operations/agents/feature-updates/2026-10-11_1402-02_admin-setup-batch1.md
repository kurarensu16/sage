## What changed and why
QA created a classroom for BSIT-1A and got ACT-1A. The admin setup audit (`docs/03-development/audits/ADMIN_SETUP_AUDIT_2026-10-11.md`) traced this to a display-vs-value mismatch, and found hard-coded colleges and name-based saving in the user form. Batch 1 fixes these. **No existing data is changed;** only new saves behave correctly.

- **`UserForm.jsx`** (C1, M1, M2, M8, M11):
  - Colleges, programs, the active term, and sections are loaded **from the database**; every value is selected and saved **by ID** (no name lookups).
  - Cascade: college → its programs → year → that program's **active-term** sections.
  - Students require a program and section.
  - Roles: Student, Faculty, Dean, Administrator (**Office removed**). Faculty and Dean need a college; Administrator has none.
  - **Email locked in edit mode:** no login-email sync exists, which was verified.
  - **User number** = next unused number per role and year.
  - Changing college, program, or year clears a section that's no longer offered. A saved previous-term section stays visible and labeled.
- **`ClassroomProvisioning.jsx`** (H1, H4, L1):
  - Subject, section, and faculty selections are **kept within the options actually shown** after any filter change (the QA bug), with a final guard on submit.
  - Only **active-term** sections are offered, with a "no sections for the active term" hint.
  - Creating is refused without an active term.
  - The list opens on the active term, labeling other terms *(Previous term)*.
  - The modal text describes automatic section enrollment and code-join approval.
- **`FacultyCreateClassroomModal.jsx`** (H4): only the instructor's own college's **active-term** sections; the fallback to other colleges' sections is removed.
- **`SectionForm.jsx`** (M9): the hard-coded school-year and semester dropdowns are replaced by one **Academic Term** dropdown from Term Settings, defaulting to the active term.
- **Checklist:** new section **B10c**, cases AS-01 to AS-14.
